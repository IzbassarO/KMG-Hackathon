# KMG Onboarding Portal — Digital Buddy

Цифровая система онбординга и адаптации новых сотрудников для АО НК «КазМунайГаз».
Прототип хакатона (**в активной разработке**).

Портал с двумя ролями (HR и сотрудник), персональным маршрутом адаптации по дням,
гид-персонажем **Digital Buddy**, обучением в формате курсов (текст / видео / тесты),
прямой связью сотрудника с HR и аналитикой адаптации.

> Бэкенда нет: всё состояние хранится в `localStorage` браузера. ИИ-часть (RAG-поиск по
> ВНД + векторная база) ведётся отдельным разработчиком и подключается из папки
> [`ai-module/`](./ai-module) — см. ниже.

---

## Стек

- **Next.js 15 (App Router) + React 19 + TypeScript**
- **TailwindCSS** + собственные shadcn-style примитивы (`components/ui`, 16 компонентов)
- **@xyflow/react 12** — flowchart-тикеты
- **State:** React Context + `useReducer` (`lib/store.tsx`), авто-персист в `localStorage`
- **Локализация:** собственный словарь RU / KK / EN (`lib/i18n.ts`) — без сторонних i18n
- **Тёмная тема:** переключатель + CSS-переменные
- **Графики:** кастомный SVG (`components/charts`), без сторонних chart-библиотек
- **Иконки:** `lucide-react`

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
npm run build        # production-сборка
npm run typecheck    # tsc --noEmit (0 ошибок)
```

Всё работает в браузере — внешний бэкенд не требуется.

## Демо-сценарий (для жюри)

1. **Лендинг** → справа вверху переключатель **языка (RU/KZ/EN)** и **тёмной темы**.
   Выберите роль и демо-аккаунт.
2. **Войдите сотрудником** (Дамир Кенжебеков). При первом входе запускается **игровой
   туториал Digital Buddy**: персонаж перемещается по реальным кнопкам и подсвечивает их.
3. После туториала — окно **Дня 1** (видео, задачи дня, прогресс).
4. На **«Мой день»** есть **demo-переключатель дня** (1 → 30 → …): план, карточки
   культуры и курсы открываются по мере роста дня. Сегодняшний день можно выполнять
   в любом порядке (free choice).
5. **Курсы** открываются напрямую в плеере (текст / видео / тесты), прогресс и
   завершение сохраняются — это видят и сотрудник, и HR.
6. **Менторство:** «Написать» / «Запросить 1:1» → войдите как HR **Нурлан Жумабаев**,
   примите встречу или ответьте — встреча появится в календаре сотрудника, придёт
   уведомление.
7. **Фидбэк** сотрудника виден HR в **Аналитике**. На дни 14/30/90 HR получает отчёт по
   адаптации (через day-jumper).
8. **Настройки → «Сбросить и начать заново»** — чистый старт демо.

## Ключевые подсистемы

| Подсистема | Где | Что делает |
| --- | --- | --- |
| **Digital Buddy** (гид, не ИИ) | `components/buddy/*`, `lib/buddy.ts` | Анимированный SVG-персонаж: игровой туториал по кнопкам, окно Дня 1, ежедневные карточки культуры, чат, напоминания об уведомлениях. Только одно окно Buddy за раз (очередь по приоритету). |
| **Маршрут по дням** | `lib/program.ts`, `lib/store.tsx` | Старт = первый вход (= День 1). Видны только задачи текущего дня; курсы/опросы/встречи открываются по `unlockDay`. Demo day-jumper для презентации. Прогресс с отметками времени. |
| **23 карточки Culture Fit** | `lib/program.ts` | Банк карточек ДУЧР (ТЗ §5.2.2), одна в день (дни 1–23). |
| **Зависимости flowchart** | `lib/flow.ts` | Шаг тикета нельзя начать, пока не завершён предыдущий; параллельные ветки независимы. |
| **Обучение (Coursera-style)** | `lib/courses.ts`, `app/employee/learning/[courseId]` | Курсы из модулей и разделов: текст (отметка о прочтении), видео (YouTube-embed), тесты с пересдачей. Завершение хранится локально, видно HR (`/hr/learning`). |
| **Связь HR ↔ сотрудник** | `lib/store.tsx` | Сообщения и запросы встреч 1:1 (принять/отклонить/ответить). Принятая встреча → в календарь + уведомление. |
| **Уведомления** | `components/shared/notifications-sheet.tsx` | Колокольчик со счётчиком непрочитанных (очищается при открытии). Генерируются из задач/встреч дня, завершения шагов тикета, сообщений HR. |
| **Фидбэк и метрики HR** | `app/employee/feedback`, `app/hr/reports` | Пульс + идеи → HR видит статистику. Трекинг входов (пунктуальность), отчёты по адаптации на 14/30/90 день, флаги риска. |
| **Локализация + тема** | `lib/i18n.ts`, `components/providers/preferences.tsx` | RU/KK/EN словарь + светлая/тёмная тема, переключатель в верхней панели. |
| **Глобальный поиск** | `components/shell/global-search.tsx` | Поиск по разделам, тикетам, статьям, сотрудникам с переходом. |
| **RAG-ассистент (заглушка)** | `lib/rag.ts`, `app/*/assistant` | TF-IDF + cosine по базе знаний с цитированием. Точка замены на боевой RAG. |

### Ссылки на видео

Все ссылки на видео (приветствие Председателя/зам. Председателя, видео курсов)
вставляются в **одном месте** — `lib/media.ts` → `VIDEO_LINKS`. Пустая строка = заглушка
плеера. Поддерживаются любые форматы YouTube (`watch?v=`, `youtu.be/`, `/embed/`).

## Роли и разделы

### Портал сотрудника (`/employee/*`)

| Раздел | Описание |
| --- | --- |
| `dashboard` | «Мой день»: текущий день, этап (1 из 4), план на сегодня (свободный порядок), карточка культуры, напоминания, demo day-jumper |
| `journey` | «Мой путь»: общая карта + flowchart-тикеты с зависимостями шагов |
| `tasks` | Задачи дня (today) + «Готово», сгруппированное по дням со временем |
| `calendar` | Календарь адаптации по дням (привязан к текущему дню), встречи 1:1 |
| `mentorship` | Контрольные точки 30/60/90 (по датам), чат и запрос 1:1 с наставником-HR |
| `learning` | Каталог курсов + плеер (текст/видео/тесты), статус «Просмотреть» по завершении |
| `documents` | Статусы документов (подтверждено / на проверке / не загружено) + загрузка |
| `knowledge` | База знаний для RAG |
| `assistant` | AI-ассистент (RAG) с цитированием и кнопкой «Очистить» |
| `team`, `feedback`, `help`, `settings`, `profile` | Команда, пульс-фидбэк, FAQ, настройки (язык/тема/сброс), профиль |

### HR-консоль (`/hr/*`)

| Раздел | Описание |
| --- | --- |
| `dashboard` | KPI, прогресс сотрудников, активность |
| `tickets`, `tickets/[id]` | Flowchart-тикеты, Kanban, конструктор, зависимости шагов |
| `employees` | Сотрудники + детальные страницы |
| `mentorship` | Входящие: запросы 1:1 (принять/отклонить) и переписка с сотрудниками |
| `calendar` | Календарь HR |
| `reports` | Аналитика: статусы/категории, фидбэк-статистика, **метрики адаптации** (курсы, пунктуальность входа, риск) |
| `learning` | Прохождение курсов по сотрудникам |
| `documents`, `knowledge`, `assistant`, `settings`, `profile` | Документы, база знаний, AI-куратор, настройки, профиль |

## Архитектура

```
app/                       App Router: лендинг + /hr/* + /employee/*
components/
  buddy/                   Digital Buddy: персонаж (SVG), туториал, чат, оркестратор
  shell/                   Sidebar, TopBar, AppShell, поиск, переключатель языка/темы
  flowchart/               node-типы + viewer + journey-strip (@xyflow/react)
  shared/                  TicketCard, AiChat, CalendarView, NotificationsSheet, ...
  charts/                  Donut, BarChart, Sparkline (SVG)
  providers/               PreferencesProvider (язык + тема)
  ui/                      shadcn-style примитивы (16)
lib/
  store.tsx                Context + reducer + helpers + авто-персист
  storage.ts               localStorage I/O (ключ kmg.onboarding.portal/v1)
  seed.ts                  демо-данные
  types.ts                 доменные модели
  program.ts               маршрут по дням, 23 карточки культуры, расписание
  flow.ts                  зависимости шагов flowchart (DAG gating)
  courses.ts               каталог курсов (текст/видео/тест)
  media.ts                 ★ единственное место для ссылок на видео
  buddy.ts                 реплики/туториал Digital Buddy
  i18n.ts                  словари RU/KK/EN
  rag.ts                   TF-IDF retrieval (точка замены на боевой RAG)
  utils.ts                 cn, formatDate, initials, uid, clamp
ai-module/                 папка-приёмник для RAG-модуля коллеги (+ данные карточек)
```

**Состояние** целиком в `localStorage`. Ключи: `kmg.onboarding.portal/v1` (основной стейт),
`kmg.buddy.*` (туториал/День 1/карточки), `kmg.locale`, `kmg.theme`. После каждой мутации
стейт сериализуется автоматически; смена статуса задачи пересчитывает прогресс тикета и
обновляет узлы flow.

## ИИ-модуль (RAG) — `ai-module/`

ИИ-часть (RAG-поиск по ВНД + векторная база ChromaDB) разрабатывается отдельным
участником и кладётся в [`ai-module/`](./ai-module). Фронтенд общается с ней по REST через
переменную `NEXT_PUBLIC_RAG_API_URL`; точка замены на стороне портала — `lib/rag.ts`.
В папке уже подготовлены 23 карточки Culture Fit: `data/culture_fit_nudges.md` (для
векторной базы) и `db/nudge_cards.sql` (для PostgreSQL).
